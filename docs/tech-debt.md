# Технический долг

## 🔥 Приоритетные задачи

### 1. Полный переход UI на динамическое расписание
- **Проблема:** `UIRenderer` и некоторые вспомогательные методы всё ещё читают `CONFIG.ROUTE_SCHEDULE`, хотя реальная логика уже живёт в `ScheduleManager`.
- **Почему важно:** расхождение источников правды → баги в журнале, маршрутах и отладке.
- **План:** 
  1. Передавать в UI только задачи из `ScheduleManager`.
  2. Удалить остатки `ROUTE_SCHEDULE` из отображения и расчётов.
  3. Добавить проверки, чтобы новая задача, активированная планировщиком, всегда отображалась в меню.

### 2. Проверка TimeManager при паузе и высоких множителях
- **Проблема:** при длительном простое на паузе `lastTimeUpdate` залипает → резкий скачок времени после возобновления.
- **План:** фиксировать время возобновления (reset `lastTimeUpdate`) и покрыть быстрым smoke‑тестом (x1/x5 + пауза).

### 3. Минимальные smoke‑тесты для ключевых менеджеров
- **Проблема:** изменения в TimeManager/ScheduleManager легко ломают симуляцию, но автоматических проверок нет.
- **План:** добавить простые скрипты/юнит‑тесты (например, через `vitest`) для:
  - корректного перехода расписания на новый день,
  - граничных сценариев stay timer после полуночи,
  - стабильности маршрутов при перепланировании.

## 📌 Наблюдения на будущее

- **Ledger для документации.** После очистки остались только актуальные файлы. Если появятся новые планы — создавать отдельные короткие заметки, а не «большие тома».
- **Сервера и npm.** Сейчас скрипты — обёртка над `python3 -m http.server`. Если появится необходимость в Node‑бэкенде, лучше добавить новый скрипт и описать его явно в README.

Все пункты выше — планы, а не выполненные задачи. По мере выполнения переносите описание в commit‑сообщения, а из этого файла удаляйте/обновляйте записи.
