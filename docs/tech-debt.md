# Технический долг

## 🔥 Приоритетные задачи

### 1. Выровнять игровую логику на ScheduleManager
- **Проблема:** Движок движения (Car/Game/PathBuilder) всё ещё рассчитывает маршруты из `CONFIG.ROUTE_SCHEDULE`, а не из фактического списка задач `ScheduleManager`.
- **Почему важно:** при расширении динамического расписания машина может «уезжать» по старому статичному плану.
- **План:**
  1. Добавить API `Game.getNextTask()`/`Game.getCurrentTask()` и использовать его вместо прямого доступа к `ROUTE_SCHEDULE`.
  2. Пересмотреть `Car.saveStateForNextDestination` и связанные вызовы, чтобы они получали «следующую локацию» из ScheduleManager.
  3. Когда весь поток перейдёт на новое расписание, удалить `CONFIG.ROUTE_SCHEDULE` или оставить только как fallback на случай пустого расписания.

### 2. Проверка TimeManager при паузе и высоких множителях
- **Проблема:** при длительном простое на паузе `lastTimeUpdate` залипает → резкий скачок времени после возобновления.
- **План:**
  - [x] Сбрасывать `lastTimeUpdate` при выходе с паузы/смене множителя.
  - [ ] Покрыть поведение быстрым smoke‑тестом (x1/x5 + пауза).

### 3. Минимальные smoke‑тесты для ключевых менеджеров
- **Проблема:** изменения в TimeManager/ScheduleManager легко ломают симуляцию, но автоматических проверок нет.
- **План:** добавить простые скрипты/юнит‑тесты (например, через `vitest`) для:
  - корректного перехода расписания на новый день,
  - граничных сценариев stay timer после полуночи,
  - стабильности маршрутов при перепланировании.
